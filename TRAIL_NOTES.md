# Trail notes

## Decisions
- 2026-11-01 Linux "type" mode refuses a whole text with characters outside printable ASCII. Measured on ydotool 1.0.4: `café` exits 0 and types `caf` plus a stray Shift; `日本語` types only Shifts. Reporting success with holes is worse than a clear stop, and the text stays on the page and on the clipboard if copying is on. Falling back to paste was rejected because it would write to the clipboard against the setting.
- 2026-11-01 Stop sending Spaces as soon as voice shows an error notice. Seen in Claude Code's own debug log: after a refused connection, the next Spaces start another attempt at once, so holding the key would retry a refusal for as long as it is held. One press now makes one attempt. A notice while "listening" still shows does not end the recording.
- 2026-11-01 Use `claude auth status` to tell a lost sign-in from a network failure, because a signed-out Claude Code draws an ordinary prompt box. It runs only after the session flags were accepted: a version too old to know `auth` would take the words as a prompt, and that must never be sent. It is outside the terminal UI like `--version`, and only its JSON is read.
- 2026-11-01 Read the hidden screen with pyte (a terminal emulator) instead of stripping escape codes from an append-only buffer. Stripping loses characters split across reads, keeps erased text, and cannot tell a menu's arrow from the prompt's. The one new dependency removes all of that, and the old "listning…" gotcha with it.
- 2026-11-01 The transcript is final when `Voice: processing…` has appeared and gone, not after 0.6 s of quiet. Recorded on 2.1.309: release -> processing 0.18 s -> final text 0.44 s. The quiet rule stays only as a fallback when that word never appears.
- 2026-11-01 A press while transcribing is refused whole, including one still held when the transcript finishes. Accepting a held one would type into an app while the shortcut's Ctrl is still down, and start recording mid-sentence. In hold mode, a press made during a cold start still counts if it is still held.
- 2026-11-01 Pause discards with Esc (documented cancel; checked on 2.1.309). A lost shortcut collects the text and keeps it on the page instead, because the user did not ask to throw it away. Neither types.
- 2026-11-01 Settings changes reach the session by comparing it with the current settings between recordings, not by a queued "restart" event, so no event can be lost.
- 2026-11-01 Runtime folder moved out of the shared temp folder (macOS: `~/Library/Caches/...`, others: `$XDG_RUNTIME_DIR`, else `~/.cache/...`). A predictable temp name can be taken first by anyone, and macOS deletes temp files unused for 3 days, which would remove the editor hook under a long-running app. The path must have no spaces: it becomes `$EDITOR`.
- 2026-11-01 Did not add a same-app window or tab check on macOS (Accessibility focused window). A wrong "focus changed" would refuse to type real dictation, and it could not be tested across real apps here; see Untried ideas.
- 2026-10-31 macOS shortcut hiding: the event tap is active (can drop events) only when the shortcut has a non-modifier key (letter, F-key, mouse button); modifier-only shortcuts keep a listen-only tap, which cannot add input latency. Tested live: Command+Option+G dictates with no stray G.
- 2026-10-31 macOS banner is a non-activating, click-through NSPanel pill above the Dock, not `osascript display notification` (that lands in Notification Center history under Script Editor's icon).

- 2026-10-31 macOS input uses a direct Quartz event tap (`mac_events.py`), not pynput. pynput 1.8.2 reports every mouse button past the third as `Button.middle` (side buttons unusable) and gives no sign when Input Monitoring is missing. Shortcuts are stored as `key:<key code>` / `mouse:<button number>`, so they follow the physical key under any layout.
- 2026-10-31 macOS refuses to type when the front app changed between release and delivery; the text stays on the clipboard. The front app is read at release, not at press, so nothing delays the first Space.

- 2026-10-25 Drive the real Claude Code CLI in a pty instead of calling its voice WebSocket with the token from `~/.claude/.credentials.json`. Anthropic's consumer terms (Feb 2026) allow subscription OAuth only inside Claude Code and Claude.ai; a homemade client risks the account.
- 2026-10-25 Settings and history live on a localhost browser page, not a native window. A Tk window was built and rejected by the user as ugly (Tk 9 on GNOME: tiny fonts, huge checkboxes); the browser page is simpler.
- 2026-10-25 The hidden session runs in its own empty folder (`<data dir>/dictation`), outside any git repo, because Claude Code feeds the folder name and git branch to dictation as word hints. The app answers the first-run "trust this folder" prompt itself; the session has no tools, so that is safe.
- 2026-10-31 Silence other audio during recording by muting the default output, not by pausing players (players live in different browsers/apps; MPRIS pause was unreliable for the user; 2026-11-01 measurements under Untried ideas show why, and that pausing plus muting would work) and not by setting volume 0 (mute leaves the level untouched). Mute after the start sound ends, unmute at release rather than after transcription.
- 2026-10-31 Keep the hidden Claude Code running by default (`idle_shutdown_minutes = 0`). A cold start costs 1-3 s, and users start talking at the press, so the first words were lost after every idle break; 250 MB is the price.
- 2026-10-31 Hidden-session memory (PSS: resident memory with shared pages split fairly, after 8 s, no children): `--safe-mode --tools ""` 184 MB; plus `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` 168 MB; plus `--strict-mcp-config --disable-slash-commands` 164 MB (kept). Voice still records with all of them. Dropping `--safe-mode` *looks* smaller (138 MB) only because startup hangs on a "Claude in Chrome detected" dialog, and it would run the user's SessionStart hooks and plugins: keep it. Every feature beyond the transcript (history, mute, typing, clipboard) lives in this app; Claude Code keeps no transcript files for the dictation folder.

## Assumptions

- 2026-11-01 `Voice: processing…` always shows between release and final text on later versions (one recording seen on 2.1.309). Check after a Claude Code update: `--test 5`, then look for "finished without seeing the processing state" in the log.
- 2026-11-01 Linux hardware not yet tried with this code; `tests/test_live_linux.py` passes with virtual devices, and the user dictated with the real F8 on 2.1.314. Check on Arch: unplug the receiver mid-hold, a real side button with grab on in a browser, Ctrl+C with grab on.
- 2026-11-01 X11 is unchecked: this machine runs GNOME on Wayland and has no xclip. Check on an X11 session: copy, paste, and type.
- 2026-11-01 Real macOS tap paths not exercised live here: permission revoked while running, Accessibility granted later, a real Command+Option+G hold through the new listener. Check: run the app, dictate, toggle the permissions in System Settings, watch the warnings.
- 2026-10-31 After Input Monitoring is granted, the app retries the shortcut every 5 s while the settings page polls; whether macOS lets a running process create the tap without a restart is unchecked. Check: start without the permission, grant it, watch the warning.
- 2026-11-01 Linux: a shortcut device that disappears (unplug, suspend) is restarted on the next settings-page poll or within 30 s; whether evdev raises OSError on suspend/resume (rather than going silent) is unchecked. Check: suspend, resume, press the shortcut.

## Gotchas

- 2026-11-01 The desktop launcher runs the `uv tool` copy, not this checkout, so a push changes nothing there until `uv tool upgrade claude-dictation-anywhere`. Check which code ran from the log's words, or from `direct_url.json` in that copy's `dist-info`.
- 2026-11-01 Linux: a signed-out Claude Code still reaches an ordinary prompt box, showing "API Usage Billing" where it showed the plan. After an expired sign-in the first hold logged "OAuth refresh failed ... 400" and "voice_stream ... HTTP 401", the screen said only "Voice connection failed. Check your network", and Claude Code then cleared its own login. `claude --debug-file <path>` shows this; it holds no audio, but read it with care.
- 2026-11-01 Linux pty: holds 20,480 bytes of unread input, so 115 s of Spaces (about 3,800) never fills it, unlike macOS. Tests that need a full pty must write until it refuses.
- 2026-11-01 Linux uinput: closing a virtual device right after writing to it loses what a reader had not read, because the reader gets ENODEV first. The kernel releases that device's held keys itself, so nothing stays held, but the release cannot be observed in a test.
- 2026-11-01 ydotool's virtual device can be grabbed (EVIOCGRAB) to see what it would type without typing into the app in front. `wpctl get-volume <missing id>` exits 0 and says "not found"; `wpctl set-mute <missing id>` exits 3.
- 2026-11-01 macOS: a child that exits with unread pty output stays in state `?E` until the master is drained or closed, so `waitpid` hangs forever. Keep draining until it has exited. `killpg` on a group with only zombies raises EPERM there, not ESRCH.
- 2026-11-01 A full pty blocks `os.write` when Claude Code stops reading (frozen at the microphone): 115 s of Spaces is more than the buffer holds. The pty is non-blocking so the recording loop stays cancellable.
- 2026-11-01 pyte prints the `u` of `ESC [ < u` (Claude Code sends it leaving the editor), so `terminal_screen` removes that sequence first, also across reads.
- 2026-11-01 CSS `display:flex` on `.row` overrides the `hidden` attribute, so hidden rows showed until `[hidden]{display:none!important}`. Found only by looking at the page in a browser.
- 2026-11-01 Linux key codes KEY_1..KEY_SLASH are not all text keys: Backspace, Tab, Enter, Left Ctrl and Left Shift sit inside that range. Use the explicit ranges in `hotkeys.TEXT_KEY_RANGES`.

- 2026-10-31 macOS: until the microphone prompt for the starting app is answered, Claude Code's native audio check blocks its whole UI at "keep holding…" (no error, Ctrl+G ignored). The app now asks for the microphone at startup and restarts a session frozen this way.
- 2026-10-31 macOS: inside pystray's AppKit loop the main thread runs no Python, so `signal.signal` handlers (SIGTERM, Ctrl+C) never fire; use `PyObjCTools.MachSignals`.
- 2026-10-31 Agent shells on this Mac run under the Claude desktop app, so macOS permissions there are the Claude app's, not the terminal's. In zsh, `log` is a builtin; use `/usr/bin/log`.

- 2026-10-25 macOS AppKit crashes if a controller worker updates the tray menu directly. Dispatch tray refresh, visibility, and stop to the main event loop; Linux permits the existing worker updates.
- 2026-10-25 A hidden `claude` started from inside another Claude Code session inherits `CLAUDE_*` / `ANTHROPIC_*` variables and shows "Not logged in". Strip them.
- 2026-10-25 `claude --bare` disables OAuth, so `/voice` is unavailable; use `--safe-mode`. `--safe-mode` plus voice settings passed through `--settings` does record. `--no-session-persistence` only works with `--print`.
- 2026-10-25 "Not logged in" appears a few seconds after the prompt draws, so a startup check misses it; detect leftover typed spaces after a hold instead.
- 2026-10-25 With escape codes stripped, Claude Code's screen often has no spaces between words (they are cursor moves), and its renderer redraws only changed cells: the recording footer reads "listning…". Match markers with whitespace removed, and never rely on the word "listening".
- 2026-10-31 Voice warm-up on a running session: "keep holding…" at 0.06 s, "listening" at 0.15 s, first microphone levels at 0.24 s after the first repeated space. Words spoken before that are lost, so nothing may run between the key press and the first Space; the start sound alone takes 0.27 s with pw-play.
- 2026-10-25 Keychron mice: the sniper button sends KEY_F8 through the receiver's keyboard interface ("Keychron  Keychron Link  Keyboard", double spaces), and receivers appear as several devices. ydotoold's virtual device also reports side buttons; ignore it or typed text echoes back.
- 2026-10-25 pystray on GNOME needs PyGObject (builds from PyPI on Arch) and the AppIndicator extension. In the built-in browser pane, `document.hidden` is true, so the page must fetch once regardless of visibility.
- 2026-10-25 A GitHub wiki's git repo (`<repo>.wiki.git`) does not exist until someone saves the first page in the web UI; `gh repo edit --enable-wiki` alone is not enough. The wiki repo is the only copy of the wiki pages; edit them there.
- 2026-10-26 After rewriting commits to drop an author, GitHub's repo-page Contributors sidebar stays stale even when the contributors API is already clean. Switching the default branch away and back to the same name does not refresh it; renaming the default branch (`master` → `main`) did, at once. The global git identity is AIkry; this repo sets a local Gerard Wu / GerardWu100 identity.
- 2026-10-31 The Claude desktop app's chat box drops the first ~10 characters (~40 ms) of ydotool typing; history had the full transcripts, and the same typing into kgx or a Brave textarea lost nothing (muting, sounds, and the banner ruled out). Felt like "dictation misses my first words" though the recording was fine: compare history with the typed text first.

## Failed approaches

- 2026-10-25 Codex dictation. *disproved*. Codex CLI 0.164 has no dictation code. The ChatGPT/Codex desktop app's global dictation is app-scoped on Linux and cannot paste there. Its `chatgpt.com/backend-api/transcribe` endpoint answers scripts with a 403 bot-check page; do not try to get around it.
- 2026-10-25 pi (pi-mono) as a lighter Codex front end. *disproved*: no built-in dictation, and its ChatGPT login covers chat models only.
- 2026-10-25 Shrinking the hidden Claude Code with Bun memory options (`BUN_OPTIONS=--smol`, `BUN_JSC_forceRAMSize`). *disproved*: RSS stayed at about 250 MB and PSS (shared memory split fairly) at about 194 MB. About 141 MB is its own working memory; about 108 MB is program code the kernel can drop and reload under memory pressure. Only quitting the session saves more.

## Open blockers

## Untried ideas

- Pause players while recording, with mute kept as the backstop. Pausing keeps your place in a video or podcast, which muting loses. Measured 2026-11-01 with `Pause`/`Play` over MPRIS (the D-Bus player interface) on Brave and Firefox, one tab: silent in 0.04-0.12 s, resumed in 0.03-0.09 s. Not enough alone: with two playing tabs both browsers answer `Paused` while the other tab keeps playing, and Web Audio pages and mpv (without its plugin) have no MPRIS at all. Design: at press, list `org.mpris.MediaPlayer2.*` with gdbus, pause those `Playing`, remember only those, still mute; at release, unmute and `Play` only those; never resume after a crash, because music starting hours later is worse. About half a day on Linux. macOS has no public equivalent: MediaRemote refuses third-party apps since 15.4 (reports only), and a media key only toggles, which starts music if none plays. Keep mute there.
- macOS same-app window check: compare the Accessibility focused window at release and before typing. Catches switching windows; cannot catch browser tabs; can falsely refuse if an app recreates its window object. About two hours plus testing in several real apps.
- Optional speech backend with an explicitly documented API (for example Groq's Whisper) for anyone wary of reusing `/voice`: needs the user's own key and explicit choice. A separate product decision, not a fix; about a day.
- Start at login (Linux `~/.config/autostart` entry, macOS LaunchAgent) as an opt-in setting: removes the manual start; about an hour.
